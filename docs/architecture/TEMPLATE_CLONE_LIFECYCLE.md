# Department templates / versions / instances / clone lifecycle
Status: CANDIDATE module-issuer review, not accepted API.
Proposed entities: DepartmentTemplate (catalog identity), DepartmentTemplateVersion (immutable digest/semantic version), DepartmentInstance (fresh identity/tenant/revision), DepartmentCloneLineage (provenance), DepartmentPosition (seat/structuralRoleKey/capacity), StaffingRequest (request lifecycle), DepartmentAssignmentLink (verified external placement ref + local membership revision), DepartmentTemplateExtensionRef (issuer/version policy pin). All field spellings are illustrative.
Version states: DRAFT → IN_REVIEW → PUBLISHED → DEPRECATED → RETIRED; published digest immutable and retired history addressable. Instance upgrade is explicit versioned migration with CAS/position mapping; no automatic template pointer mutation.
Instantiate/clone: authorized current template/source+revision+allowlist digest, tenant-scope default same tenant, reject untrusted extension payload. Copy only approved structural slots and nonsecret config; allocate fresh department/position IDs, instance history/lineage and return idempotent auditable receipt. All new instances unstaffed, with zero assignment/staffing requests/grants/secrets/tasks/leases/effects. Cross-tenant clone denied by default. Status UNKNOWN or missing trusted policy blocks completion.
Independent versioning: templateVersion != moduleVersion/build != extensionVersion != consumer contractVersion. Existing staffed positions cannot be removed/migrated without verified discharge/drain. Safety/cross-owner review required before admission.
